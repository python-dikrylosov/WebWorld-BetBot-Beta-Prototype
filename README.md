## 🎯 Концепция <a name="concept"></a>

Цель этого Beta-прототипа — исследовать и продемонстрировать концепцию гибридной системы, объединяющей возможности *дообученной модели мира для веба* (на базе WebWorld), *внешнего аналитического ИИ* (например, Qwen-Coder) и *инструментов автоматизации браузера* (Selenium) для автоматизации процесса анализа спортивных событий (в данном случае, мужского тенниса ATP) и выполнения букмекерских ставок на основе этого анализа.

## 🔧 Компоненты <a name="components"></a>

- **Doobtrained WebWorld Model:**
    - **Роль:** Модель мира, обученная понимать структуру веб-страниц (например, A11y Tree) и *планировать последовательности веб-действий* (`click`, `fill` и т.д.).
    - **Функции:**
        - Анализ текущего состояния веб-страницы.
        - Генерация действий для навигации по сайту.
        - Использование действия `send_msg_to_user` для *запроса внешней информации* (например, аналитики матча).

- **`qwen-coder` (или другая внешняя модель/инструмент):**
    - **Роль:** Внешняя модель, отвечающая за *анализ данных* и *принятие решений* о ставке.
    - **Функции:**
        - Получение *данных из интернета* (статистика тенниса).
        - *Анализ* полученных данных (например, сравнение игроков, статистики).
        - *Принятие решения* о потенциальной ставке (например, "ставка на фаворита", "рекомендуемая сумма").

- **Selenium:**
    - **Роль:** Инструмент для *физического взаимодействия* с браузером.
    - **Функции:**
        - Открытие и управление браузером.
        - Выполнение конкретных действий (клик, ввод текста), указанных *дообученной моделью WebWorld*.

- **Python-скрипт-агента:**
    - **Роль:** *Центральный управляющий элемент*, связывающий все компоненты.
    - **Функции:**
        - Управление циклом: захват состояния -> вызов дообученной WebWorld -> интерпретация вывода (включая `send_msg_to_user`) -> вызов `qwen-coder` для анализа -> возврат результата в контекст WebWorld -> выполнение действий через Selenium.

## 🚀 План Действий <a name="plan"></a>

1.  **Скачивание:**
    - Скачать модель WebWorld (например, `WebWorld-8B`) и датасет `WebWorldData`.
2.  **Подготовка данных:**
    - Изучить формат `WebWorldData` (JSONL, разговоры).
    - Перевести текстовую часть `WebWorldData` на **русский язык**, используя `qwen-coder`.
    - Провести ручную проверку качества перевода, особенно структуры A11y Tree и синтаксиса действий.
    - Подготовить **собственные данные**, описывающие сценарии взаимодействия с русскоязычными сайтами и интеграции с внешней моделью анализа (используя `send_msg_to_user`).
    - Объединить переведённый `WebWorldData` и собственные данные.
3.  **Fine-tuning:**
    - Дообучить выбранную модель WebWorld на объединённом русскоязычном датасете.
4.  **Разработка интеграционного агента:**
    - Создать Python-скрипт, реализующий логику агента.
    - Интегрировать вызовы дообученной модели WebWorld.
    - Интегрировать вызовы `qwen-coder` для анализа теннисных матчей.
    - Интегрировать Selenium для выполнения веб-действий.
    - Реализовать логику обработки `send_msg_to_user` и возврата результатов анализа в контекст WebWorld.

## ✅ Возможности <a name="capabilities"></a>

- **Автоматизированная навигация:** Возможность перемещаться по веб-сайтам букмекерских контор.
- **Интерпретация данных:** Чтение и понимание информации на страницах.
- **Интеграция аналитики:** Возможность вызова внешних моделей для анализа данных.
- **Выполнение цепочек действий:** Последовательное выполнение действий.
- **Адаптация к языку:** Возможность работы с русскоязычными интерфейсами благодаря дообучению.

## ⚠️ Ограничения <a name="limitations"></a>

- **Точность прогнозов:** Успех всей системы **крайне зависим** от *способности внешней модели анализа* (например, `qwen-coder`) давать *точные* прогнозы. Современные ИИ не идеальны в строгом вероятностном анализе.
- **Надёжность WebWorld:** Модель может ошибаться в понимании сложных или динамических веб-страниц.
- **Блокировки сервисов:** Букмекерские конторы активно борются с ботами.
- **Юридические аспекты:** Использование автоматизации может нарушать правила платформ или законы.
- **Сложность реализации:** Интеграция нескольких сложных систем требует значительных технических усилий.

## 🛠️ Требования <a name="requirements"></a>

- **Python:** >= 3.8
- **Библиотеки Python:**
    - `torch` (для запуска моделей Hugging Face)
    - `transformers` (для работы с моделями Hugging Face)
    - `huggingface_hub` (для загрузки моделей)
    - `selenium`
    - `webdriver-manager` (рекомендуется для автоматической настройки драйверов)
    - `datasets` (для работы с датасетами Hugging Face, опционально)
    - `playwright` (для генерации A11y Trees, если требуется, опционально)
